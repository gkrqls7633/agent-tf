# agent-tf 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 프로젝트 폴더에서 명령 한 줄로 투입하는 Claude Code plugin `agent-tf`(팀장 skill 하나와 팀원 에이전트 6명)를 만들고 개인 GitHub 에 올립니다.

**Architecture:** 저장소 하나가 plugin 이자 마켓플레이스입니다(`source: "./"`). 팀장은 `skills/lead/SKILL.md`, 팀원은 `agents/*.md` 입니다. 프로젝트마다 다른 것(명령, 배포, UX 기준)은 plugin 에 넣지 않고 각 프로젝트의 `CLAUDE.md` 에서 읽습니다.

**Tech Stack:** Claude Code plugin(마크다운과 JSON). 검증은 `claude plugin validate`, `claude plugin details`.

**Spec:** `docs/specs/2026-11-20-agent-tf-design.md`

## Global Constraints

- plugin 이름과 마켓플레이스 이름은 모두 `agent-tf`. 팀장 명령은 `/agent-tf:lead`.
- 팀원 6명: `planner`, `backend`, `frontend`, `reviewer`, `qa`, `devops`.
- 관리자 확인 세 곳(조각마다 모두): 최종 기획안 승인, 리뷰와 자동 테스트를 마친 개발 완료 보고(대기), 커밋과 배포 승인.
- 기획자와 개발자의 상호 피드백은 최대 2회. 합의 못 한 점은 관리자에게 질문.
- 문서와 보고는 결론 세 줄로 시작, 기획안은 한 화면 안팎, A1 같은 기호 번호 금지.
- 과제 파일은 조각마다 하나, `docs/tf/YYYY-MM-DD-<주제>.md`. 팀원 보고는 파일로 남기지 않음.
- 팀원은 커밋하지 않음. 배포 승인을 커밋 허락으로 보지 않음.
- 모든 문서와 프롬프트는 한국어. 이모지 없음.
- 커밋은 마지막 Task 에서 관리자 확인 뒤 한 번만 합니다.

## Review Focus

- 프로젝트 `CLAUDE.md` 에 테스트나 배포 방법이 없을 때: 팀장이 추측해서 진행하지 않고 처음에 관리자에게 묻는다(Task 3 의 SKILL.md 에 명시, Task 4 에서 확인).
- 관리자가 개발 완료 보고에 답하지 않고 다른 말을 할 때: 팀장은 QA 로 넘어가지 않는다("다음 진행" 같은 명시적 승인만 통과).
- 진행 중 새 요구가 나올 때: 지금 조각에 넣지 않고 과제 파일의 "다음 후보" 에 적고 묻는다.
- 세션이 끊긴 뒤 다시 `/agent-tf:lead` 를 부를 때: `docs/tf/` 의 진행 중 과제 파일을 찾아 이어 간다.
- 백엔드나 프런트가 없는 프로젝트: 해당 팀원을 건너뛴다.

### Task 2: 팀원 에이전트 6명

**Files:**
- Create: `agents/planner.md`, `agents/backend.md`, `agents/frontend.md`, `agents/reviewer.md`, `agents/qa.md`, `agents/devops.md`
- 출발점: `D:\workspace-newai\agent-hub\.claude\agents\` 의 `feature-planner`, `backend-architect`, `frontend-builder`, `code-reviewer`, `integration-qa` (devops 는 새로 씀)

**Interfaces:**
- Produces: 에이전트 이름 6개(팀장이 `subagent_type` 으로 부름). 모든 팀원의 보고는 같은 틀입니다: `결론`(세 줄 이하) / `바꾼 파일` / `확인한 것`(실행한 명령과 결과) / `관리자에게 물을 것`.

- [ ] **Step 1:** 각 파일에 frontmatter `name`, `description`(팀장이 언제 부르는지 한 줄), 필요하면 `tools` 를 둡니다. reviewer 는 읽기 도구만, devops 는 Bash 포함.
- [ ] **Step 2:** 본문은 공통으로 "시작 전에 프로젝트 `CLAUDE.md` 와 `.claude/rules/` 를 읽는다", "커밋하지 않는다", "요청 범위 밖은 고치지 않고 `관리자에게 물을 것` 에 적는다", 위 보고 틀을 둡니다.
- [ ] **Step 3:** 역할별 핵심을 둡니다.
  - planner: 결론 세 줄로 시작하는 기획안, 완료 기준, 화면 흐름, 관리자와 사용자 구분, 사용자 단계 수를 줄였는지 점검, "끝나면 바로 쓸 수 있는 조각" 하나만.
  - backend, frontend: 기획안 검토 모드(구현 방법과 걸리는 점을 짧게 회신)와 구현 모드. 테스트를 먼저 씀. frontend 는 기존 화면 구성 요소와 스타일을 먼저 찾아 씀. 팀장이 나눠 준 파일만 고침.
  - reviewer: 바뀐 부분만 보고, 버그와 보안과 프로젝트 규칙 위반을 심각도(막음, 고쳐야 함, 참고)와 `파일:줄` 로 보고. 고치지 않음. 프로젝트 테스트 명령을 실행해 결과를 붙임.
  - qa: 테스트와 서버를 실제로 돌림, 로컬 Playwright 로 화면 확인(좁은 폭과 넓은 폭 스크린샷, 카드 밖 넘침 확인), API 응답과 화면 파싱 코드의 칸 이름 대조, 완료 기준 대조. 부작용 있는 버튼은 정확한 글자로 고름.
  - devops: 프로젝트 `CLAUDE.md` 의 배포 방법만 씀. 팀장이 관리자 배포 승인을 전달했을 때만 실행. 방법이 없으면 실행하지 않고 보고.
  - ai-hub-service 전용 내용(langfuse, `/api/v1`, `_workspace/`, 브랜드 색상, Lucide)은 넣지 않습니다.
- [ ] **Step 4: 검증** — Run: `claude plugin validate D:\workspace-newai\agent-tf`. Expected: agents 6개 오류 없음.

### Task 3: 팀장 skill 과 과제 파일 양식

**Files:**
- Create: `skills/lead/SKILL.md`, `skills/lead/task-template.md`

**Interfaces:**

- Produces: 명령 `/agent-tf:lead`. 과제 파일 양식(제목 / 결론 세 줄 / 최종 기획안 / 완료 기준 / 진행 상태 체크리스트 / 다음 후보).

- [ ] **Step 1:** frontmatter `name: lead`, `description` 에 "관리자가 agent-tf 팀에게 일을 맡길 때" 를 씁니다.
- [ ] **Step 2:** 시작 절차를 씁니다. `docs/tf/` 에 진행 중 과제 파일이 있으면 이어 갈지 묻습니다. 프로젝트 `CLAUDE.md` 에 테스트, 배포, UX 기준이 없으면 처음에 묻고 적어 두자고 제안합니다.
