# agent-tf 설계

## 결론

- 어느 프로젝트에든 명령 한 줄로 투입하는 Claude Code plugin `agent-tf` 를 만듭니다. 관리자(사용자)는 팀장에게만 말합니다.
- 팀장은 메인 세션이 따르는 skill(`/agent-tf:lead`)입니다. 팀원 6명은 에이전트 파일입니다. 팀원은 다른 팀원을 직접 부를 수 없어서, 모든 지시와 보고는 팀장을 거칩니다.
- 관리자가 확인하는 곳은 세 곳이고, 조각마다 모두 거칩니다. 최종 기획안 승인, 리뷰를 마친 개발 완료 보고, 배포 승인입니다.

## 왜 만드는가

- 일하는 방식이 "관리자 한 명과 전문 에이전트 팀" 으로 바뀌었습니다. 이 팀을 프로젝트마다 다시 만들지 않고 투입만 하려고 합니다.
- 지난 작업에서 반복된 문제를 진행 규칙으로 막으려고 합니다.
  - 설계 문서가 길고 결론을 찾기 어려웠습니다.
  - 진행할수록 항목(A1~10, B1~10, U1~10)과 과제가 늘었습니다.
  - 일부가 이미 커밋돼 중간에 멈출 수 없었습니다.
  - 관리자 기능과 사용자 기능을 구분하지 않거나, 화면이 어렵게 설계됐습니다.

## 목표와 하지 않을 것

목표
- 팀장 skill 하나와 팀원 에이전트 6명으로 기획부터 배포까지 한 흐름을 돌립니다.
- plugin 을 켜는 것만으로 프로젝트에 투입됩니다.

하지 않을 것
- 이번에는 agent-hub 전용 hook(예: seed 스크립트 차단)이나 UX 기준을 만들지 않습니다. plugin 이 끝난 뒤 agent-hub 투입 준비로 따로 진행합니다.
- 팀원끼리 직접 메시지를 주고받는 구조는 만들지 않습니다.
- 마켓플레이스 공개 배포는 하지 않습니다. 로컬 저장소에서 설치합니다.

실패로 볼 것(돌아가더라도)
- 단계마다 보고서 파일이 쌓여 관리자가 읽을 것이 늘어나는 것
- 진행 중에 범위가 관리자 승인 없이 커지는 것
- 팀장이 팀원 보고를 그대로 옮겨 길게 보고하는 것

## 흐름

```
관리자 ─ 요청 ─▶ 팀장
1. planner   기획안 초안
2. backend, frontend 가 초안을 검토하고 planner 와 피드백을 주고받음(최대 2회) → 최종 기획안
   [관리자 확인 1] 최종 기획안 승인
3. backend, frontend 구현(서로 겹치지 않으면 동시에)
4. reviewer 코드 리뷰와 자동 테스트 확인. 문제가 나오면 3으로 되돌림
   [관리자 확인 2] 기능별 개발 완료 보고. 관리자가 "다음 진행" 이라고 할 때까지 기다림
5. qa       실제 실행, 화면 확인, 기획안의 완료 기준 대조
   문제가 나오면 3으로 되돌림. 발견한 문제만 고치고 범위는 넓히지 않음
   [관리자 확인 3] 커밋과 배포 승인
6. devops   배포
```

- 요청 하나가 여러 조각으로 나뉘면 조각마다 1부터 6까지 전체 흐름을 돕니다. 어느 조각에서 멈춰도 배포된 것은 완성된 상태입니다.
- 두 번의 피드백 안에 합의하지 못한 점은 팀장이 관리자에게 질문으로 올립니다.
- 기획 단계에서 관리자와 일반 사용자를 구분하고, 사용자가 거치는 단계 수를 적게 잡는 것을 planner 의 기본 점검으로 둡니다.

## 팀원

| 에이전트 | 하는 일 |
|---|---|
| `planner` | 요구를 완료 기준이 있는 기획안으로 만듭니다. 화면 흐름과 역할(관리자, 사용자)을 정합니다. |
| `backend` | 서버 쪽 검토와 구현. 테스트를 먼저 쓰고 구현합니다. |
| `frontend` | 화면 쪽 검토와 구현. 기존 화면 구성 요소를 먼저 찾아 씁니다. |
| `reviewer` | 바뀐 코드의 버그, 보안, 프로젝트 규칙 위반을 봅니다. 고치지 않고 보고만 합니다. |
| `qa` | 테스트와 서버를 실제로 돌리고, 화면을 확인하고, 완료 기준과 대조합니다. |
| `devops` | 프로젝트에 적힌 방법으로 배포합니다. 팀장이 관리자 승인을 전달할 때만 실행합니다. |

## 진행 규칙

- **작게 쪼개기**: 한 번에 "끝나면 바로 쓸 수 있는 조각" 하나만 기획하고 구현합니다. 어느 조각에서 멈춰도 커밋된 것은 완성된 상태여야 합니다.
- **범위 고정**: 진행 중 나온 새 아이디어는 지금 조각에 넣지 않고 과제 파일의 "다음 후보" 에 한 줄로 적습니다. 넣을지는 관리자가 정합니다.
- **문서 형식**: 기획안과 보고는 결론 세 줄로 시작합니다. 기획안은 한 화면 안팎입니다. A1, U3 같은 기호 번호를 쓰지 않습니다.
- **과제 파일 하나**: 조각마다 프로젝트에 파일 하나(`docs/tf/YYYY-MM-DD-<주제>.md`)만 둡니다. 최종 기획안, 진행 상태, 다음 후보가 여기 있습니다. 세션이 끊겨도 이 파일로 이어 갑니다. 팀원 보고는 파일로 남기지 않고 팀장이 받아 요약합니다.
- **보고**: 팀장은 팀원 보고를 모아 결론부터 짧게 보고합니다. 근거가 필요하면 파일 경로와 줄 번호를 붙입니다.
- **커밋**: 팀원은 커밋하지 않습니다. 커밋은 관리자가 요청할 때만 팀장이 합니다. 배포 승인을 받을 때 팀장은 "커밋하고 배포할까요?" 처럼 커밋 여부를 함께 묻습니다. 배포 승인을 커밋 허락으로 간주하지 않습니다.
- **동시 구현**: backend 와 frontend 는 같은 작업 폴더에서 일합니다. 팀장이 맡길 때 각자 고칠 파일을 나눠 주고, 겹치면 차례로 맡깁니다. worktree 는 쓰지 않습니다(팀원이 커밋하지 않으므로 합치기 어렵습니다).
- **화면 확인 도구**: qa 는 로컬 PC 의 Playwright 로 화면을 확인합니다. 프로젝트 `CLAUDE.md` 에 다른 방법이 적혀 있으면 그것을 따릅니다. plugin 에 MCP 서버를 넣지 않습니다.

## 프로젝트에서 읽는 것

팀원의 역할과 진행 방식은 plugin 에 있고, 프로젝트마다 다른 것은 그 프로젝트의 `CLAUDE.md` 와 `.claude/rules/` 에서 읽습니다.

- 테스트, 실행 명령
- 배포 방법
- 화면과 UX 기준, 코딩 규칙

투입할 때 이 중 빠진 것이 있으면 팀장이 처음에 관리자에게 묻고, 답을 그 프로젝트의 `CLAUDE.md` 에 적자고 제안합니다.

## 투입 방법

- 저장소: `D:\workspace-newai\agent-tf`. 관리자 전용 비공개 git 원격 저장소에 올립니다. 이 저장소가 plugin 이자 마켓플레이스입니다.
- 투입은 프로젝트 폴더에서 명령 한 줄입니다. 마켓플레이스 등록과 plugin 설치를 project 범위로 묶습니다.

  ```powershell
  claude plugin marketplace add <git 주소> --scope project; claude plugin install agent-tf@agent-tf --scope project
  ```

- project 범위라서 설정이 그 프로젝트의 `.claude/settings.json` 에 남습니다. 같은 저장소를 받은 사람도 같은 팀을 씁니다(원격 저장소 접근 권한이 있을 때).
- 이 한 줄은 저장소 `README.md` 맨 위에 둡니다.
- agent-hub 의 `.claude/agents` 6개와 `.claude/rules` 5개(ai-hub-service 에서 옮겨 온 것)는 이 plugin 으로 대체되므로 agent-hub 투입 단계에서 걷어냅니다.
- 팀원 에이전트는 그 6개를 출발점으로 삼습니다. 역할, 계약 준수, 경계 교차 검증처럼 범용인 내용은 살리고, ai-hub-service 전용 내용(langfuse, `/api/v1`, `_workspace/` 보고서, 브랜드 색상 등)은 빼서 프로젝트 쪽 규칙으로 넘깁니다.

## 검토한 방식

| 방식 | 장단점 | 결정 |
|---|---|---|
| 개인 plugin 저장소 | 프로젝트별로 켜고 끔. 버전 관리와 공유 가능. 설정 파일 두세 개가 더 필요함 | 채택(관리자 선택) |
| 사용자 폴더(`~/.claude`) | 가장 간단함. 모든 프로젝트에 항상 들어가고 버전 관리를 따로 해야 함 | 제외 |
| 프로젝트마다 `harness` skill 로 생성 | 프로젝트마다 복사본이 생겨 서로 달라짐 | 제외 |

## 만드는 사람에게 맡기는 것

- plugin 과 마켓플레이스 설정 파일의 정확한 형식(현재 Claude Code 문서 기준으로 확인)
- 팀원 에이전트의 도구 권한과 모델 지정
- 과제 파일의 세부 양식
설계자가 정한 것(관리자 확인 대상): plugin 이름과 마켓플레이스 이름을 모두 `agent-tf` 로 둠, 테스트 단계는 reviewer 가 자동 테스트 결과를 확인하는 것으로 둠, 과제 파일 위치 `docs/tf/`.
